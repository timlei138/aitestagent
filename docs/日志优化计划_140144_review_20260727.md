## Task 1：permission auto-handle 改为 loop-until-clear + 高安全天花板

**问题**：`_MAX_CHAINED_POPUPS = 3`（`tools/click.py:478`），联想日历有 4+ 个连续权限请求，第 4 个弹窗超出上限未被 auto-deny 接住。

**原则判定（修订）**：写死 5 是 magic-number——这次 4 个、下次可能 6 个，不是稳定不变量。正确的契约是"检测到权限弹窗就一直 auto-handle 到没有为止"，再套一个高安全天花板当熔断。

**改动**：
- `tools/click.py` L476-523：将固定 `for _popup_i in range(_MAX_CHAINED_POPUPS)` 改为 `while True` + 安全天花板：
  ```python
  _PERMISSION_CHAIN_SAFETY_CEILING = 10  # 熔断上限，非功能上限
  for _popup_i in range(_PERMISSION_CHAIN_SAFETY_CEILING):
      info = _detect_permission_popup(ctx, timeout=3.0)
      if not info:
          break  # 无弹窗即退出，不是"用完配额"
      ...  # 原有 auto-handle 逻辑不变
  ```
- `_MAX_CHAINED_POPUPS` 常量重命名为 `_PERMISSION_CHAIN_SAFETY_CEILING`，语义从"功能上限"变为"熔断保护"
- 循环退出条件不变（`if not info: break`），只是把天花板从 3 提到 10

**效果**：4 个弹窗、6 个弹窗都能正常接住；10 个以上才触发熔断（异常情况）。不再随 App 变化反复改数字。

## Task 2：`set_permission_intent` 弹窗在屏却传空 permission → 结构化错误

**问题**：日志 L888，权限弹窗 GrantPermissionsActivity 已在屏时，Agent 调了 `set_permission_intent(action="deny")` 但没传 `permission`。此时正确做法是用 `respond_to_permission_dialog(button=...)`。

**原则判定**：✅ 真·工具契约。确定性事实（弹窗在屏 + 参数为空）→ 结构化错误 + 正确工具名，不随场景增长。

**改动**：
- `tools/perceive_tools.py` L345-370：在 `set_permission_intent` 中，`action` 非空且 `permission` 为空时，先调 `_permission_popup_buttons(ctx)` 检查弹窗是否在屏：
  ```python
  if action and not permission:
      _popup = _permission_popup_buttons(ctx)
      if _popup:
          _activity, _controls = _popup
          _btns = "|".join(t for t, _, _ in _controls)
          return make_result(
              ERROR,
              f"当前屏幕存在权限弹窗({_activity})，请直接用 "
              f"respond_to_permission_dialog(button=\"...\") 响应（可见按钮: {_btns}）；"
              f"或传入具体 permission 类型后再用 click() 自动处理。",
              _permission_evidence(_activity, _controls),
          )
  ```

**不做什么**：不自动帮 Agent 点弹窗（那是 LLM 的决策），只给确定性事实 + 正确工具名。

## Task 3：NOT_FOUND 基于 auto-handler 状态追加提示（非关键字匹配）

**问题**：Agent 手动 `click("允许")` → NOT_FOUND，弹窗其实已被 auto-handler 处理消失。

**原则判定（修订）**：~~关键字匹配 _GRANT_BUTTONS/_DENY_BUTTONS~~ 是"字样补丁"。正确做法是基于 auto-handler 自己写的确定性状态——它刚处理完弹窗时会留下 evidence，这是事实，不是猜。

**改动**：
- `tools/click.py`：auto-handler 处理完权限弹窗后，在 `ctx` 上记录 `_last_auto_permission_time`（`time.monotonic()`）：
  ```python
  # auto-handler 成功处理弹窗后（L503-512 区域）
  ctx._last_auto_permission_time = time.monotonic()
  ```
- click 返回 NOT_FOUND 时，检查该状态（3s 内有效）：
  ```python
  # NOT_FOUND 返回路径中
  _auto_ts = getattr(ctx, "_last_auto_permission_time", 0)
  if _auto_ts and (time.monotonic() - _auto_ts) < 3.0:
      msg += " | 提示：权限弹窗刚被 auto-handler 自动处理（可能已消失），请 get_screen_info() 确认当前页面。"
  ```

**效果**：从"目标文案像权限按钮就提示"（关键字补丁）变成"auto-handler 刚跑过就提示"（事实契约）。判断条件是 auto-handler 自己写的时间戳，有限且稳定。

## Task 6：perceiver 过滤系统 UI 噪声

**问题**：`perceive()` 返回的 `understanding.elements` 含状态栏、通知图标、导航栏等系统 UI 元素，大量 `<无文本>` 容器。`get_screen_info`（`tools/__init__.py:152`）只是 perceive 输出的格式化壳，噪声根源在 `device/perceiver.py` 的 `perceive()`（L234）。

**原则判定**：✅ 基础设施。按元素自身 resource-id/class 过滤（有限且稳定）。**不按 context_path 祖先匹配**——否则会把挂在系统容器下的 App 内容误删。

**改动**：
- `device/perceiver.py` `perceive()` 的元素过滤阶段（生成 elements 列表时），增加过滤：
  ```python
  _SYSTEM_UI_RESOURCE_IDS = frozenset({
      "status_bar", "system_icons", "notificationIcons",
      "nav_buttons", "navigation_bar", "recent_apps",
  })
  _SYSTEM_UI_CLASSES = frozenset({
      "StatusBarWindowView", "NavigationBarWindowView",
      "SystemBarsWindowView",
  })

  def _is_system_ui_noise(el) -> bool:
      """只按元素自身属性判断，不看祖先 context_path。"""
      rid = (el.resource_id or "").split("/")[-1] if el.resource_id else ""
      if rid in _SYSTEM_UI_RESOURCE_IDS:
          return True
      cls = (el.class_name or "").split(".")[-1] if el.class_name else ""
      return cls in _SYSTEM_UI_CLASSES
  ```
- 在 elements 生成后、返回前过滤：`elements = [e for e in elements if not _is_system_ui_noise(e)]`

**不做什么**：
- **不按 context_path 过滤**：避免误删挂在系统容器下的 App 内容
- **不影响权限弹窗**：`respond_to_permission_dialog` 走独立的 `dump_hierarchy()` 路径（`perceive_tools.py:148`），不经过 perceive 的 elements
- **不影响通知栏交互**：`open_notification()` 是独立的设备操作，过滤只影响 perceive 的元素列表

**验证**：跑现有测试确认元素识别不受影响，特别注意 `test_perceiver_label_suppression.py`。
